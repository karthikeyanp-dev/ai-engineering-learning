## Introduction

You've mastered the fundamentals, built RAG systems, designed agents, fine-tuned models, and learned system design. Now it's time to put it all together into **capstone projects** that demonstrate your capabilities to employers, collaborators, and the community.

Your portfolio is your strongest signal in the AI engineering job market. Hiring managers consistently say that candidates with deployed, well-documented projects stand out dramatically from those with only course certificates. A single impressive project with a live demo, clean code, and thoughtful README is worth more than ten tutorial follow-alongs.

This lesson gives you four capstone project ideas (pick 1-2), a framework for portfolio building, and guidance on showcasing your work effectively.

<Callout type="important" title="Quality Over Quantity" client:load>
  Build 1-2 excellent projects, not 5 mediocre ones. Each project should have: a live demo, comprehensive README, clean code, tests, and monitoring. Treat it like production software — because that's what hiring managers are evaluating.
</Callout>

## Capstone Project Ideas

### Project 1: AI Research Assistant

**Difficulty:** Advanced | **Timeline:** 3-4 weeks | **Skills demonstrated:** RAG, Agents, Multi-source retrieval

Build an AI assistant that helps researchers explore academic papers, synthesize findings, and generate literature reviews.

**Core Features:**
- Multi-source ingestion (arXiv PDFs, web pages, YouTube transcripts)
- Hybrid RAG with re-ranking (semantic + keyword + citation graph)
- Agent-based research workflows (search → read → synthesize → cite)
- Conversation memory with session persistence
- Citation generation in multiple formats (APA, MLA, BibTeX)

**Tech Stack:**
```
Backend: FastAPI + LangGraph for agent orchestration
Vector DB: Qdrant (open-source, self-hostable)
Embeddings: text-embedding-3-small (OpenAI) or BGE (local)
LLM: GPT-4o for synthesis, GPT-4o-mini for classification
Frontend: Next.js or Streamlit
Deployment: Vercel (frontend) + Railway/Fly.io (backend)
```

### Project 2: AI Code Review Agent

**Difficulty:** Advanced | **Timeline:** 2-3 weeks | **Skills demonstrated:** Agents, Tool use, GitHub API

Build a GitHub bot that automatically reviews pull requests with intelligent, contextual feedback.

**Core Features:**
- PR diff parsing and understanding
- Codebase context retrieval (related files, conventions, past reviews)
- Multi-aspect review (bugs, security, performance, style, tests)
- Inline comment generation with suggestions
- Confidence scoring (only comment when confident)

### README Best Practices

Your README is the landing page of your project. Include:

1. **Hero section** — One-line description + demo GIF/video (above the fold)
2. **Features** — Bullet points of what it does (not how)
3. **Architecture diagram** — Mermaid or image showing system design
4. **Quick start** — Get running in < 5 minutes
5. **Tech decisions** — Why you chose each component (shows engineering judgment)
6. **Results** — Evaluation metrics, benchmarks, screenshots
7. **Lessons learned** — What you'd do differently (shows maturity)

<Callout type="warning" title="Common Portfolio Mistakes" client:load>
  Avoid: no live demo, no README, tutorial code copy-pasted without modification, too many half-finished projects, no tests, hardcoded API keys in code. Each of these signals junior-level work to reviewers.
</Callout>

### Deployment Platforms

| **Railway** | Backend APIs | $5/month credit | Yes |
| **Fly.io** | Docker containers | 3 shared VMs | Yes |

### Demo Best Practices

1. **Live URL that works** — Test it monthly; broken demos are worse than no demo
2. **Pre-loaded examples** — Don't make reviewers set up API keys to try your project
3. **Loading states** — Show progress during LLM calls (streaming preferred)
4. **Error handling** — Graceful failures with helpful messages
5. **Mobile responsive** — Recruiters often check on phones

## Building in Public

### Why Build in Public?

- **Accountability** — Public commitment increases completion rate
- **Networking** — Attracts collaborators, mentors, and hiring managers
- **Content** — Each project update is a blog post or tweet
- **Feedback** — Early feedback prevents going down wrong paths

### Where to Share

- **Twitter/X** — Short updates, demos, learnings (tag #buildinpublic)
- **LinkedIn** — Longer posts about architecture decisions, project updates
- **Dev.to / Hashnode** — Technical blog posts with code examples
- **YouTube** — Demo videos and architecture walkthroughs
- **Discord communities** — AI Engineer, LangChain, MLOps

### Content Calendar Template

```
Week 1: "Starting my capstone project — here's the architecture I chose and why"
Week 2: "Built the RAG pipeline — here are my chunk size experiments"
Week 3: "Added evaluation — my RAGAS scores and what I learned"
Week 4: "Deployed! Here's the live demo and what I'd do differently"
```
